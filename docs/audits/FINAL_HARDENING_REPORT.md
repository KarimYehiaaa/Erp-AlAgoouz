## 1. ملخص تنفيذي (Executive Summary)

تم إنجاز خطة التحصين والترقية الشاملة لنظام **بن العجوز ERP** لرفعه إلى أعلى معايير الجاهزية الإنتاجية والموثوقية التشغيلية عبر البيئات الأربع للتشغيل:
1. **النسخة المحلية (Local / On-Premise)**: البيئة الرئيسية التي تعمل دون انقطاع ومستقلة 100% عن الإنترنت.
2. **الخادم السحابي (Cloud / Vercel / Supabase)**: المزامنة المركزية والوصول السحابي الآمن.
3. **تطبيق سطح المكتب (Desktop POS / Electron)**: طوابير المزامنة المحلية وقفل العمليات المتزامنة والطباعة الشبكية.
4. **تطبيق الهاتف المحمول (Mobile / Capacitor)**: لوحة تحكم الإدارة وعمليات الجرد الآمنة.

## 2. المحاور الرئيسية للإصلاح والتحصين

### 2.1 توحيد المعمارية وإزالة بقايا مفهوم "الفروع"
- **تأكيد نموذج المحل الواحد**: تحديث `CONTEXT.md` والتوثيق المعماري؛ النظام يُدار كمحل تجاري واحد يملك مخازن متعددة (`warehouses`).
- **تنظيف المصطلحات وواجهات المستخدم**: استبدال كافة التسميات القديمة مثل "فرع" أو "كاشير الفرع" بـ "المحل" / "مبيعات المحل" / "المخزن المعني" عبر واجهات المبيعات (`SalesSummaryCard`, `RetailSalesPanel`, `StockTab`, `ExcelMode`, `MenuPageLayout`) والتقارير.
- **إزالة الصلاحيات والمحددات القديمة**: تطبيق الترحيلات `075_remove_legacy_branch_scope.sql` و `076_remove_legacy_branch_permission.sql` لعزل أي اعتماد على الحقول القديمة.

### 2.2 الأمان والمصادقة (P1 Security Hardening)
- **إعادة هيكلة خط أنابيب الـ Idempotency**:
  - إزالة `app.use(requireIdempotency)` من النطاق العام غير المحمي لمنع هجمات استرجاع الردود (Cached Response Replay).
  - تثبيت الـ Middleware داخل مسارات التعديل الحساسة بعد `authenticate` و `authorize`.
  - تطبيق مبدأ الرفض الفوري (Fail-Closed) للطلبات التي ترسل ترويسات مصادقة منتهية أو غير موثقة (إرجاع كود 401).
  - عزل مفاتيح الـ Idempotency بشكل صارم لكل مستخدم (`user:${userId}:${method}:${path}:${key}`).
- **توكنات تجاوز المدير الذرية الموثقة (Manager Override Tokens)**:
  - استبدال التخزين في ذاكرة العملية (`Map`) بجدول قاعدة بيانات مركزي دائم `manager_override_tokens` مع استهلاك ذري `UPDATE ... WHERE used_at IS NULL RETURNING ...`.
  - منع هجمات إعادة الاستخدام (Replay Attacks) وإرجاع كود `MANAGER_OVERRIDE_ALREADY_USED` فور تكرار التوكن.
  - تطبيق هجرة إسقاط قيود المفتاح الأجنبي `078_drop_manager_override_fkeys.sql` لضمان استقرار العمليات العنقودية وبيئات الاختبارات.

### 2.3 الأمان التشغيلي وحدود الحماية (P2 Security & Reliability)
- **تحصين مزامنة الدفعات (`POST /sales/batch-sync`)**:
  - فرض حد أقصى لحجم الدفعة: 50 فاتورة.
  - فرض حد أقصى لعدد أصناف الفاتورة الواحدة: 100 صنف.
  - فرض حد أقصى لإجمالي الأصناف في كامل الدفعة: 500 صنف لمنع استنزاف موارد الخادم.
  - تفعيل معدل تدفق مخصص (`batchSyncLimiter`) بواقع 20 دفعة/دقيقة لكل مستخدم.
- **سد ثغرة قراءة الإشعارات (IDOR Prevention)**:
  - إلزام وجود `userId` الصريح في `markNotificationRead` و `markAllNotificationsRead`.
  - رفض أي طلب يفتقر إلى معرف المستخدم برمز خطأ `400` ورمز `USER_REQUIRED`.
- **أمان ملاحة تطبيق الهاتف (Capacitor Security)**:
  - تقييد نطاق الملاحة في `frontend/capacitor.config.ts` بالنطاقات الرسمية المشفرة (`https://agoouz.vercel.app`, `https://agoouz-api.vercel.app`) في بيئة الإنتاج، مع حصر البروتوكولات غير المشفرة على خادم التطوير المحلي.

### 2.4 التوافقية الثنائية وقواعد البيانات (Database & Script Parity)
- **دعم `DATABASE_URL` في كافة السكربتات**:
  - تحديث سكربتات الترحيل والفحص (`migrate-supabase.ts`, `db-check.ts`, `audit_db.js`, `db-test.mjs`, `backup-system.ts`) لتدعم الاتصال الموحد عبر `DATABASE_URL` بجانب المتغيرات المنفصلة.
  - فرض خروج السكربتات برمز خطأ غير صفري (`process.exit(1)`) عند حدوث أي فشل في الترحيل أو الاتصال.
- **عقد النسخ الاحتياطي والاستعادة المشفر**:
  - إدراج جدول `manager_override_tokens` ضمن عقد النسخ الاحتياطي `RESTORE_ORDER` في `backupService.ts`.
  - التحقق من شمولية كافة جداول المهاجرات الـ 65 ضمن النسخ والاستعادة.
