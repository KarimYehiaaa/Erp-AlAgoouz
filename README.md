# بن العجوز ERP (Bin Al-Agoouz ERP)

نظام لإدارة محل واحد ونقطة البيع والمبيعات والمخزون والحسابات، مع إمكانية وجود مخازن متعددة داخل نفس النشاط. راجع [سياق النشاط](CONTEXT.md).

---

## 🚀 التقنيات المستخدمة (Tech Stack)

- **Backend:** Node.js (إصدار التطوير في `.nvmrc`)، Express.js، TypeScript، PostgreSQL، Redis / BullMQ، WebSocket عبر `ws`.
- **Frontend:** Vue 3 (Composition API)، Vite، Pinia، TypeScript، SCSS، Chart.js.
- **Mobile / Desktop:** Capacitor (Android/iOS) + Electron / Desktop POS.
- **Testing & Quality:** Vitest، فحص TypeScript، اختبارات قاعدة بيانات محلية معزولة. عدد الاختبارات ونتائجها يُستخرجان من التشغيل الحالي.

---

## ⚡ التشغيل السريع (Quickstart)

إعدادات بناء الواجهة موضحة في `frontend/.env.example`، وهي مستقلة عن إعدادات قاعدة البيانات. الويب يستخدم API من أصل الصفحة افتراضيًا، والموبايل يستخدم موقع بن العجوز. تُقبل عناوين الشبكة المحلية وفق سياسة الاتصال الخاصة بالنسخة؛ Android Release يتطلب HTTPS. لإضافة خادم HTTPS آخر، أعلن أصله الكامل بما فيه المنفذ في `VITE_API_URL` أو `VITE_TRUSTED_SERVER_URLS` وقت البناء، دون مسار أو بيانات دخول. لا تُقبل خوادم عامة غير معلنة من الإعدادات المحفوظة، ولا تضع أسرارًا في متغيرات `VITE_` لأنها تُضمّن في الواجهة.

يتطلب المشروع Node.js 24 (الإصدار المحدد في `.nvmrc`) وnpm وقاعدة PostgreSQL محلية للاختبارات والتشغيل المعزول. ثبّت اعتماديات الويب والخادم من الجذر واعتماديات Electron من مجلده المستقل:

```bash
# تثبيت قابل لإعادة الإنتاج من ملفات القفل
npm ci
npm ci --prefix desktop-pos

# أنشئ إعدادًا محليًا من القالب ثم ضع بيانات قاعدة محلية
cp .env.example .env

# ابدأ PostgreSQL المحلي وRedis ثم جهّز المخطط
docker compose --profile local-db up -d postgres redis
npm run setup-db -w backend

# شغّل الخادم والواجهة في نافذتين من جذر المشروع
npm run dev -w backend
npm run dev -w frontend
```

يعمل الخادم افتراضيًا على المنفذ 3000 والواجهة على 5173. تفاصيل Windows وDocker وAndroid في [دليل المطور](docs/README.md). لا تضع أسرار قاعدة البيانات أو مفاتيح توقيع Android داخل Git؛ جهّزها محليًا أو في مدير أسرار بيئة النشر.

يمكن استخدام `npm run setup` بعد إعداد `.env` بدل تنفيذ التثبيت وتهيئة القاعدة يدويًا. المعالج يثبت الويب والخادم من قفل الجذر وElectron من قفله، وينتظر صحة PostgreSQL وRedis إذا اخترت Docker المحلي، ثم يهيئ القاعدة ويبني الواجهة عند الطلب. يتوقف عند فشل أي خطوة؛ وفي وضع قاعدة مشتركة لا يبدأ قاعدة محلية ثانية ولا يتجاوز حارس الترحيلات البعيدة. `scripts/windows/setup.ps1` يشغّل المعالج نفسه.

عند تشغيل المعالج بإجابات موجّهة من برنامج آخر، يستهلك المعالج وحده هذه الإجابات؛ لا ترثها أوامر التثبيت والتهيئة والبناء. يغلق قناة الإدخال الموجّهة بعد اكتماله أو فشله حتى لا يبقى معلقًا. لا يغلق إدخال جلسة الطرفية التفاعلية.

## 🧪 الفحص والاختبارات (Verification & Quality)

```bash
# فحص دقة الأنواع (TypeScript Typecheck)
npm run typecheck

# الفحص المحلي الموحد الشامل (Migrations + Isolated Tests)
npm run check:local

# تشغيل الخادم وإغلاقه على قاعدة جديدة مؤقتة (من دون بيانات المحل)
npm run test:boot

# فحص الأمان للاعتماديات التشغيلية
npm run security:audit

# بناء حزمة الإنتاج
npm run build -w frontend
```

## 🐳 خيارات الاستضافة والتشغيل (Deployment)

لإنشاء نسخة قابلة للنقل، شغّل `npm run backup` بعد ضبط اتصال القاعدة و`BACKUP_ENCRYPTION_KEY` بطول 32 حرفًا على الأقل. ينتج أرشيفًا في `full-backups` يضم الشيفرة الحالية والملفات المرفوعة ولقطة قاعدة مشفرة جديدة، ويفك الأرشيف للتحقق من بصمات الملفات قبل إعلان النجاح. أدوات النسخ في Windows تستعمل الأمر نفسه. احتفظ بمفتاح التشفير الأصلي بشكل آمن منفصل؛ الأسرار والاعتماديات والأبنية ومفاتيح توقيع التطبيقات وطوابير الكاشير غير المتزامنة لا تُضمّن في الأرشيف. خطوات الاستعادة موجودة داخل `RESTORE.md` في كل نسخة؛ اختبرها على قاعدة معزولة أولًا.

1. **الويب وAPI:** إعداد الجذر لـVercel يبني `frontend/dist`، ويمكن تشغيل API والخدمات الدائمة عبر Docker.
2. **سطح المكتب:** تطبيق Electron مستقل بنقطة بيع محلية ومزامنة مع API.
3. **الموبايل:** واجهة Capacitor تُبنى كحزمة Android. يلزم SDK محلي ومفتاح توقيع محفوظ خارج المستودع لإصدار Release.

يمكن ضبط الويب والخادم المحلي وتطبيقات الأجهزة على قاعدة PostgreSQL واحدة، بما فيها Supabase. كل بيئة تحتاج إعداد اتصالها الآمن بشكل مستقل؛ بيانات الاتصال غير مضمنة في المشروع.

يسمح الديسكتوب باتصال HTTP على الجهاز نفسه عبر `localhost` أو `127.0.0.1` أو `0.0.0.0`، بما فيها المنافذ المخصصة. استخدم HTTPS موثوقًا للاتصال من جهاز آخر. إصدار Android Release يستخدم HTTPS؛ إعداد اتصال صالح في الديسكتوب لا يعني أنه صالح تلقائيًا على الهاتف.
