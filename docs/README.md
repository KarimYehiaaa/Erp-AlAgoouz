# دليل تشغيل بن العجوز ERP

يحتوي المشروع على واجهة ويب وواجهة Android مبنية بـ Capacitor، وخادم Express، ونقطة بيع Electron، وخدمة تحليلات Python اختيارية. يعتمد خادم API على PostgreSQL؛ يمكن تشغيل القنوات كلها على قاعدة Supabase واحدة عند إعداد كل نسخة تشغيل بعنوان الاتصال نفسه.

## المتطلبات

- Node.js 24 وnpm. ملف `.nvmrc` يحدد الإصدار المستخدم في CI وDocker.
- PostgreSQL 14 أو أحدث للتشغيل المحلي أو الاختبارات التكاملية. يمكن استخدام قاعدة PostgreSQL محلية أو Supabase؛ لا تضع بيانات الاتصال الحقيقية في Git.
- Git لنسخ المشروع. Android SDK وJDK مطلوبان فقط لبناء تطبيق Android، وPython 3.12 مطلوب فقط لخدمة التحليلات الاختيارية.

## إعداد جديد على جهاز آخر

من مجلد المشروع:

```sh
cp .env.example .env
npm ci
npm ci --prefix desktop-pos
```

في Windows PowerShell استخدم `Copy-Item .env.example .env` بدل `cp`.

عدّل `.env` ليتصل بقاعدة محلية أو أعد إعدادات Supabase من مدير الأسرار للبيئة التي ستشغّلها. استخدم أسرارًا منفصلة وقوية لـ`JWT_SECRET` و`BACKUP_ENCRYPTION_KEY`. تطوير الخادم يرفض قاعدة البيانات البعيدة افتراضيًا؛ لا تسمح باتصال نسخة التطوير بقاعدة المحل المشتركة إلا عند الحاجة وبعد فهم أن الطلبات ستصل إلى بياناتها.

للتشغيل المحلي المعزول، اضبط `DB_USER` و`DB_PASSWORD` في `.env`، ثم ابدأ خدمات قاعدة البيانات وRedis:

```sh
docker compose --profile local-db up -d postgres redis
npm run setup-db -w backend
```

بعد جاهزية قاعدة البيانات، افتح نافذتين من جذر المشروع:

```sh
npm run dev -w backend
```

```sh
npm run dev -w frontend
```

يعمل API افتراضيًا على `http://localhost:3000` وواجهة Vite على `http://localhost:5173`. لبناء الواجهة وتشغيلها من خادم API الواحد استخدم `npm run build -w frontend` ثم `npm run start -w backend`.

للتشغيل الدائم، استخدم خدمة Windows الموثقة في دليل الإعداد أو Docker. أُزيلت أوامر npm القديمة الخاصة بـPM2 لأنها كانت تعتمد على تثبيت عام خارج المشروع ولم تكن مستخدمة في مسارات التشغيل المعتمدة. يبقى `config/pm2/ecosystem.config.cjs` للتوافق مع التركيبات القديمة فقط؛ لم تُحذف برامج PM2 المثبتة على الجهاز أو تتغير عملياتها الحالية.

## سطح المكتب وAndroid

يحدد إعداد Vercel ملفات التشغيل والترحيلات وشهادة Supabase العامة والشعار اللازم لخدمات الخادم. لا يضم مجلد الخادم كاملًا، حتى لا تدخل نسخ البيانات والسجلات وكاش الاختبارات وشهادات localhost في طلب ضم الملفات. إذا احتاج نشر مخصص إلى شهادة CA أخرى، فأضف ملف الشهادة العامة المطلوب صراحةً إلى إعداد النشر؛ لا تضم مجلد الشهادات كله أو أي مفتاح خاص.

في Vercel يقرأ الخادم إعداداته من بيئة الاستضافة ويتجاهل ملفات `.env` المحلية. يلزم توفير إعدادات قاعدة البيانات وأسرار تسجيل الدخول والتشفير في المشروع السحابي نفسه؛ لن تُكمل ملفات جهاز المطوّر إعدادًا ناقصًا هناك. يظل التشغيل المحلي يكتشف `.env` في مجلد الخادم ثم جذر المشروع كما سبق.

تُثبّت اعتمادية سطح المكتب بأمر `npm ci --prefix desktop-pos` لأن Electron POS مشروع مستقل بقفل اعتماديات خاص به. لتشغيله محليًا انتقل إلى `desktop-pos` وشغّل `npm run dev`.

لبناء Android، ثبّت Android SDK وJDK المتوافقين مع Gradle، واجعل SDK ظاهرًا عبر `ANDROID_HOME` أو `ANDROID_SDK_ROOT` أو ثبّته في مسار Android Studio الافتراضي. بعد اكتشاف SDK، يجهّز سكربت البناء `frontend/android/local.properties` مؤقتًا ويدعم الحروف العربية في المسار؛ لا يحتاج الجهاز الجديد إلى نقل هذا الملف. يستعيد السكربت محتوى الملف الأصلي كما كان بعد نجاح البناء أو فشله، ويحذف الملف المؤقت إذا لم يكن موجودًا سابقًا. إذا لم يجد SDK يتوقف البناء برسالة خطأ ولا يغيّر إعدادًا محليًا. بناء Release يتطلب إعداد `ANDROID_KEYSTORE_PATH` و`ANDROID_KEYSTORE_PASSWORD` و`ANDROID_KEY_ALIAS` و`ANDROID_KEY_PASSWORD` و`ANDROID_SIGNING_LINEAGE_PATH` صراحةً في بيئة البناء أو مدير أسرار؛ لا يبحث السكربت عن مفاتيح أو كلمات مرور مخفية في مجلد المستخدم، ولا تنسخ مفتاح التوقيع أو كلمة مروره إلى المشروع أو Git. يجب استخدام شهادة الإصدار الحالية المعتمدة وسلسلة الانتقال من الشهادة القديمة، كما هو موضح أدناه. يتوفر أيضًا `npm run mobile:build` لبناء الواجهة ومزامنتها مع مشروع Capacitor.

يشغّل `scripts/deployment/build-apk.bat` على Windows سكربت البناء نفسه بوضع Debug، ويحفظ الناتج باسم `BinAlAgoouz-Manager-Debug.apk` حتى لا يختلط بملف Release أو يُستخدم بالخطأ كتحديث للمستخدمين. نسخة Debug لها معرّف تطبيق مختلف ولا تحدّث النسخة المثبتة. عند استخدامه، يجب أن يكون SDK مثبتًا أو محددًا عبر متغيرات البيئة أو `local.properties`؛ لا يتطلب نقل هذا الملف من جهاز آخر.

في Windows PowerShell، حمّل القيم من مدير الأسرار المعتمد ثم شغّل البناء؛ لا تكتب كلمات المرور مباشرة في ملف المشروع أو سطر الأوامر المحفوظ:

```powershell
$env:ANDROID_KEYSTORE_PATH = '<path-to-securely-provisioned-keystore>'
$env:ANDROID_KEY_ALIAS = '<existing-release-key-alias>'
$env:ANDROID_SIGNING_LINEAGE_PATH = '<securely-provisioned-legacy-to-current-lineage>'
# Inject ANDROID_KEYSTORE_PASSWORD and ANDROID_KEY_PASSWORD from your secret manager.
.\scripts\deployment\build-apk.ps1 -BuildType Release
```

على الأجهزة ذات الذاكرة المحدودة يمكن تمرير `-GradleWorkers 1 -GradleHeapMiB 1024` لتقليل توازي البناء وذاكرة Java، دون تغيير خصائص التطبيق أو التوقيع. مخرجات واجهة Android في `frontend/dist-native`، ويقرأها Capacitor من هذا المجلد؛ مخرجات الويب والمحل تبقى في `frontend/dist` حتى لا يستبدل بناء الموبايل ملفات الويب.

تحتاج النسخة الجديدة أيضًا إلى سلسلة التوقيع السابقة عبر `ANDROID_SIGNING_LINEAGE_PATH`، حتى يقبل Android 13+ الانتقال من الـAPK القديم إلى شهادة الإصدار الحالية مع صلاحية نقل بيانات التطبيق. ينشئ البناء نسخة مؤقتة من السلسلة تسمح بنقل البيانات فقط وتلغي ثقة المشاركة والصلاحيات والمصادقة والرجوع للشهادة القديمة المكشوفة؛ يبقى الملف الأصلي محفوظًا. يقرأ البناء التوقيع المضمّن والبيانات الفعلية داخل APK باستخدام أدوات SDK، ويتحقق من اسم الحزمة ورقم الإصدار والحد الأدنى للنظام، ثم يحفظ ملف بصمة بجوار النسخة. يحفظ APK السابق ببصمته في `backups`، ويستعيد الناتج السابق إذا فشل استبدال ملف البصمة. نجاح هذا الفحص لا يثبت حفظ البيانات على الهاتف؛ جرّب التحديث فوق النسخة المثبتة دون حذف التطبيق، وتحقق من الإعدادات وتسجيل الدخول والبيانات قبل توزيع النسخة على بقية الأجهزة.

Android Release يتصل عبر HTTPS؛ استخدم الموقع الأونلاين أو خادمًا محليًا بشهادة موثوقة على الهاتف. عنوان HTTP المحلي على المنفذ 3000 متاح للويب وسطح المكتب؛ لا تسمح نسخة Android Release بهذا النقل غير المشفر. نسخة Debug تسمح بـHTTP فقط لبوابة محاكي Android القياسية `10.0.2.2`؛ أما الهاتف الفعلي فيحتاج HTTPS موثوقًا. لا يعتمد المشروع على عنوان IP ثابت لشبكة المحل. يضبط غلاف البناء نوع النسخة للواجهة تلقائيًا ويستعيد متغيرات البيئة بعد البناء.

## الاختبارات والفحوص

```sh
npm run typecheck
npm test
npm run check:local
```

تحتاج اختبارات backend التكاملية إلى PostgreSQL محلي معزول. يشغّلها `npm run test:local -w backend`؛ حارس الاختبار يرفض الاتصال بقاعدة بعيدة. لا تستخدم أوامر تهيئة قاعدة البيانات أو الترحيل على بيانات المحل كجزء من فحص جهاز جديد.

مرّر كلمة مرور PostgreSQL المحلية عبر `POSTGRES_PASSWORD` أو `DB_PASSWORD`، أو احفظها في `backend/.postgres.local`؛ الملف مستثنى من Git. لا يعتمد مشغّل الاختبارات على كلمة مرور محلية افتراضية.

لاختبار المتصفح مع الخادم الحقيقي وقاعدة مؤقتة، ثبّت Chromium مرة واحدة عبر `npx playwright install chromium` ثم شغّل `npm run test:web-api`. يبني الأمر الواجهة داخل `frontend/.playwright-dist` ويستخدم المنفذ 4173؛ يجب أن يكون متاحًا. يختبر الدخول والجلسة وعرض المنتج وإعادة تحميله مع حجب الاتصال الخارجي، ثم يحذف قاعدة الاختبار. لا يعدّل قاعدة المحل أو مخرجات بناء الويب والموبايل.

## النسخ الاحتياطي والنقل

بعد إعداد اتصال القاعدة، اضبط `BACKUP_ENCRYPTION_KEY` بطول 32 حرفًا على الأقل ثم شغّل `npm run backup` من الجذر. أدوات `scripts/windows/backup-system.ps1` وملف Batch تستعمل المسار نفسه وتعيد رمز الفشل عند تعذر النسخ.

ينتج أرشيف `.tar.gz` فريدًا داخل `full-backups`، ويضم `project/` للشيفرة الحالية والملفات المرفوعة، و`database/` للقطة مشفرة جديدة، و`manifest.json` للبصمات والأحجام، و`RESTORE.md` للخطوات. يُفك الأرشيف وتُقارن بصماته قبل إعلان النجاح. لا تستبدل الأداة نسخة كاملة بأرشيف Git عند فشل الضغط.

احفظ مفتاح التشفير الأصلي منفصلًا بشكل آمن؛ ملف `.env` وكلمات المرور والمفاتيح الخاصة والاعتماديات ومخرجات البناء لا تدخل الأرشيف. طوابير الكاشير غير المتزامنة وملفات مستخدم Electron تحتاج نسخ الجهاز الخاصة بها، ومفاتيح توقيع Android تحتاج حفظًا آمنًا منفصلًا. اختبر الاستعادة على قاعدة معزولة قبل استخدامها على بيانات المحل.

## البناء والنشر

لبناء صورة الواجهة المنفصلة، استخدم جذر المستودع كسياق: `docker build -f frontend/Dockerfile .`. تحتاج هذه الصورة إلى خدمة backend على الشبكة نفسها بالاسم `backend` والمنفذ 3000 وفق إعداد nginx؛ أما Compose الحالي فيقدم الواجهة من صورة الخادم المتكاملة.

- أمر بناء الويب المعتمد هو `npm run build -w frontend` ومخرجه `frontend/dist`. الإعداد الجذري لـVercel يشغّل الأمر نفسه وينشر هذا المجلد.
- يبني Docker الصورة من جذر المستودع: `docker build -t bin-alagoouz-erp -f Dockerfile .`. يتطلب التشغيل إعداد أسرار الاتصال وقاعدة البيانات في البيئة.
- خدمة التحليلات مستقلة واختيارية؛ تعليماتها في [دليلها](../analytics-service/README.md). وظائف التحليل المدمجة في ERP تبقى متاحة عند إيقافها.
- يلزم ضبط أسرار وبيانات اتصال منفصلة في Vercel أو Docker أو الجهاز المحلي. مشاركة قاعدة البيانات تعني ضبط كل بيئة على عنوان قاعدة Supabase نفسه، ولا تعني تضمين كلمة المرور في ملفات المشروع.

## إنشاء نسخة PDF من التوثيق

المصدر المعتمد هو `docs/documentation_source.html`. بعد تثبيت Chrome أو Edge، شغّل `node docs/generate_docs_pdf.cjs` لإنتاج `docs/Bin_AlAgoouz_ERP_Complete_Documentation.pdf`. يكتشف السكربت المستعرض من `PATH` ومواقع تثبيته المعتادة؛ ويمكن تحديد مساره عبر `DOCS_BROWSER_BIN` أو `EDGE_BIN` أو `CHROME_BIN`. استخدم `DOCS_OUTPUT_DIR` لتوجيه ملف PDF إلى مجلد إخراج آخر.

## توليد عروض أسعار PDF من API

واجهة عروض الأسعار الحالية تصدّر PDF داخل المتصفح. أما مسار `POST /api/v1/quotes/pdf` فيحتاج Chrome أو Chromium أو Edge مثبتًا في بيئة الخادم. يمكن تحديد ملفه التنفيذي، أو اسم أمره الموجود في `PATH`، عبر `CHROME_PATH`. عند ترك المتغير فارغًا تبحث الخدمة في `PATH` ومواقع التثبيت المعتادة للنظام؛ وعند تحديد قيمة غير صالحة ترفضها بدل استعمال متصفح آخر بصمت.

ينشئ كل طلب ملف مستخدم خاصًا بالمتصفح داخل مجلده المؤقت، دون تعطيل sandbox، وينظف المجلد عند النجاح أو الفشل. تؤخذ هوية الشعار من `assets/logo.png` داخل المشروع، وتستخدم تواريخ العرض وصلاحيته توقيت المحل بالقاهرة. صور Docker الحالية لا تضم المتصفح، ولم يُثبت توافره في Vercel؛ يجب تجهيز هذا المتطلب قبل الاعتماد على توليد PDF من API في تلك البيئات. لا تحتاج عملية التصدير الحالية داخل واجهة الويب إلى هذا المتغير.

## ملفات الجهاز المحلي

تُنشأ ملفات `.env` و`frontend/android/local.properties` وبيئات Python ومخرجات `dist` وAPK ومثبت Electron محليًا، وهي مستثناة من Git. يحتاج الجهاز الجديد إلى تثبيت المتطلبات الخارجية وإعداد أسراره الخاصة قبل البناء أو التشغيل؛ لا يحتوي المستودع على قاعدة البيانات أو أسرار النشر أو مفاتيح توقيع Android.
