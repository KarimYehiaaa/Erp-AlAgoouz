# بن العجوز ERP — نقطة البيع المكتبية (Desktop POS)

## 📌 نظرة عامة
تطبيق كاشير ونقاط بيع مكتبي متكامل مبني بتقنيات **Electron + Vue 3 + TypeScript + Vite** ومجهز بحزمة تثبيت ويندوز مستقلة (**NSIS Windows Installer**).

---

## 🏗️ المعمارية التقنية (Architecture)

1. **طبقة الواجهة (Renderer Process):**
   - Vue 3 (Composition API) + Pinia + Vue Router + SCSS.
   - دعم كامل للغة العربية (RTL) مع شاشات سريعة لفتح وإغلاق الوردية، إدارة السلة، والمدفوعات (نقدي، فيزا، انستاباي، آجل).
2. **محرك النظام المكتبي (Main Process - Electron):**
   - تحكم كامل بالنوافذ وتجهيزات الهاردوير.
   - قاعدة معاملات غير متصلة (Offline Queue Storage) مع كتابة ذرية آمنة (Atomic File Writes) واستعادة تلقائية من النسخ الاحتياطية في حال انقطاع الكهرباء المفاجئ.
3. **محرك المزامنة التلقائي في الخلفية (PosSyncWorker):**
   - فحص دوري لاتصال الخادم المركزي كل 15 ثانية مع قفل التزامن لمنع التداخل (Concurrency Lock).
   - ترحيل الفواتير المعلقة عبر اتصال مشفر حصراً (HTTPS/TLS في الإنتاج) عبر `POST /sales/batch-sync` مع إرفاق توكن الجلسة (JWT Bearer).
   - حماية ضد التكرار (Idempotency) باستخدام معرّفات `sync_id` UUID فريدة ومفهرسة بقاعدة بيانات PostgreSQL.
   - نظام إعادة محاولة صارم: حتى 10 محاولات كحد أقصى، ثم التوقف عن إعادة المحاولة الآلية والاحتفاظ بالمعاملة مع تسجيل الخطأ ووقت التحديث للمراجعة اليدوية.
   - حماية متانة التخزين المحلي: إذا أكد السيرفر نجاح المزامنة وفشلت كتابة القرص المحلي، لا يتم احتساب الفاتورة كمزامنة منعاً للنجاح الوهمي.
4. **مشغلات الهاردوير (Hardware Drivers & Verification Status):**
   - **طابعة الإيصالات الحرارية (Receipt Printer):**
     - تم إثباتها برمجياً عبر عقود Socket TCP 9100 وعقود Windows Spooler الآلية.
     - *الحالة المادية:* تتطلب اختباراً ميدانياً على عتاد الطابعة الفعلي (Physical Verification Required).
   - **درج النقدية (Cash Drawer):**
     - تم إثبات نبضة ESC/POS القياسية (`0x1b, 0x70, 0x00, 0x19, 0xfa`) وإرجاع حالة `NOT_SUPPORTED` رسمياً عند محاولة الفتح المباشر عبر Spooler ويندوز دون درايفر مخصص منعاً للنجاح الوهمي.
     - *الحالة المادية:* تتطلب اختباراً ميدانياً على الدرج الفعلي (Physical Verification Required).
   - **قارئ الباركود (Barcode Scanner):**
     - تم إثبات التقاط ومطابقة الباركود واختبار الأحداث برمجياً.
     - *الحالة المادية:* تتطلب اختباراً ميدانياً بجهاز الماسح الضوئي الفعلي (Physical Verification Required).

## 📦 حزمة التثبيت لنظام ويندوز (Production Installer)

ينتج أمر البناء ملف تثبيت رسمي لنظام ويندوز:
```text
desktop-pos/release/AlAgoouz-POS-Setup-1.0.0.exe
```

- **نوع الحزمة:** NSIS Windows Installer (x64).
- **إصدار Electron:** 44.4.3 (Supported stable production series).
- **إصدار Electron Builder:** 26.15.3 مع `--publish never`.
- **المميزات:**
  - إنشاء اختصار رسمي على سطح المكتب وفي قائمة ابدأ (Start Menu).
  - إمكانية اختيار مجلد التثبيت وإلغاء التثبيت النظيف عبر لوحة تحكم ويندوز.
  - يعمل كبرنامج ويندوز أصيل ومستقل تماماً دون الحاجة لأي أدوات تطوير (Node.js/npm/Git) على جهاز الكاشير.
  - تخزين بيانات المعاملات غير المتصلة بأمان في مسار نظام التشغيل (`%APPDATA%\AlAgoouz-POS`).

## 🌐 سياسة الاتصال وأمن النقل (Central Backend & Transport Security Policy)

- **سياسة فرض التشفير (Strict HTTPS Enforcement):**
  - في بيئة الإنتاج والنسخ المجمعة (`app.isPackaged`)، يُمنع منعاً باتاً استخدام بروتوكول `http://` غير المشفر للخوادم الخارجية، ويتم رفض الرابط فوراً على مستوى الـ Renderer والـ Main Process مع رسالة توضيحية.
  - يُسمح حصرياً ببروتوكول `http://` للنطاقات المحلية الخاصة بالتطوير (`localhost`, `127.0.0.1`, `0.0.0.0`).
- **مصدر الإعدادات الموحد:** يتم التحقق من عنوان الخادم قبل الحفظ في التخزين المحلي، وتمريره للـ API ومحرك المزامنة في وقت واحد.
- **استمرارية العمل دون اتصال (Offline Durability):**
  - حفظ ذري متين (Atomic Durable Local Queue) باستخدام ملفات مؤقتة (`.tmp`) ونسخ احتياطي (`.bak`) واستعادة تلقائية عند تلف الملف الأساسي.
  - معالجة واضحة لسيناريوهات الفشل A إلى E مع منع النجاح الوهمي عند تعطل الكتابة المحلية.

## 🛠️ أوامر التطوير والتشغيل

```bash
# الانتقال لمجلد نقاط البيع
cd desktop-pos

# تثبيت الاعتماديات
npm install

# تشغيل بيئة التطوير
npm run dev

# تشغيل الاختبارات الآلية
npm test

# بناء وإنشاء ملف التثبيت النهائي (.EXE)
npm run electron:build
```
