# خطة إصلاح أخطاء مراجعة 2026-09-26

النطاق: الحالة الحالية لمساحة العمل، بما فيها التعديلات المحلية الموجودة قبل هذه الخطة. لا تشمل الخطة نشرًا أو تعديل بيانات تشغيلية.

| الأولوية | الخلل | معيار قبول الإصلاح |
| --- | --- | --- |
| حرجة | استبدال نقاط ولاء غير متاحة لتجاوز حد خصم الكاشير | يرفض الخادم الاستبدال بلا عميل، أو برصيد غير كافٍ، أو بخصم أقل من قيمة النقاط؛ يتحقق من الرصيد بقفل داخل معاملة البيع. تعديل البيع المكتمل يتطلب موافقة مدير لغير الأدوار الإدارية ولا يقبل استبدال نقاط جديدًا. |
| متوسطة | حد نقاط الولاء يعتمد على الإجمالي بعد الاستبدال | تحسب واجهتا الويب ونقاط البيع الحد من الإجمالي قبل نقاط الولاء وبعد الخصم اليدوي، وتتركان إجماليًا موجبًا متوافقًا مع الترحيل المحاسبي الحالي. |
| متوسطة | إعادة محاولة اتصال نقاط البيع المحلي تستخدم `localhost` مرة أخرى | الطلب المعاد يصل إلى `127.0.0.1` مرة واحدة فقط عند فشل الاتصال بـ`localhost`. |
| منخفضة | صفحة مبيعات فارغة تُظهر إجمالي سجلات صفرًا | يبقى العدد الكلي للفلاتر صحيحًا حتى عند تجاوز آخر صفحة. |
| منخفضة | تحذير lint في صفحة الدخول | يمر فحص lint بلا تحذير. |

## التحقق

- اختبارات المبيعات والأمان على قاعدة PostgreSQL محلية معزولة تُحذف بعد التشغيل.
- اختبارات الواجهة ونقاط البيع والتحليلات.
- فحص الأنواع وlint وبناء الواجهة وتطبيق نقاط البيع.
- مراجعة الفروقات النهائية للتأكد من عدم تغيير تعديلات أخرى في مساحة العمل.

ملاحظة محاسبية: لا يدعم مسار البيع الحالي إجماليًا صفرًا؛ لذلك تحدد الواجهات استبدال النقاط بحيث يبقى مبلغ موجب، بدل إنشاء بيع لا يُرحّل له قيد محاسبي.
